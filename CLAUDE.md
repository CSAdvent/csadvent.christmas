# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Critical Rules

**These rules override all other instructions:**

1. **NEVER commit directly to main** - Always create a feature branch and submit a pull request
2. **Conventional commits** - Format: `type(scope): description`
3. **GitHub Issues for TODOs** - Use `gh` CLI to manage issues, no local TODO files. Use conventional commit format for issue titles
4. **Pull Request titles** - Use conventional commit format (same as commits)
5. **Branch naming** - Use format: `type/scope/short-description` (e.g., `feat/calendar/countdown`)
6. **Working an issue** - Always create a new branch from an updated main branch
7. **Check branch status before pushing** - Verify the remote tracking branch still exists. If a PR was merged/deleted, create a new branch from main instead
8. **Write tests** - All new/refactored code requires tests where applicable
9. **Run validation before commits** - Run `dotnet build` and `dotnet test` and verify no errors before committing
10. **No co-authors** - Do not add co-author information on commits or pull requests
11. **No "generated by" statements** - Do not add generated-by statements on pull requests

## Project Overview

The C# Advent site (csadvent.christmas), replacing the legacy site Matt Groves built. The legacy code is a feature spec only; nothing is ported from it.

- **.NET 11** Blazor Web App (RC with a go-live license until GA in November 2026), **PostgreSQL** for every season (archives render from the database, never static pages), **Aspire** for local development, telemetry and deployment.
- **`docs/runbook.md`** is the yearly cycle and what each alert means. Keep it current when a change affects what organizers do.
- **`docs/deployment.md`** is deploying and the one-time Azure, GitHub and credential setup. The README stays a short introduction.
- **Matt Groves is the founder and always a host**: credit him first (`Site:Organizers`, `Founder: true`).

**Glossary:** a season is keyed by year, with a *slot* (a "spot" in the UI) per day and *part* (1 a day in 2017, 2 since). A *claim request* asks for a spot and an organizer approves it. *Substitutes* are "backup posters". The *blurb* is the line every post from 2026 on must open with, saying it's part of C# Advent and linking back. *Contributors* are people signed in with GitHub; *organizers* are the admins.

## Commands

```bash
aspire run                         # Run the AppHost (site, Postgres, migrations, pgweb, MailPit)
dotnet build CSAdvent.slnx         # Build everything
dotnet test                        # All tests (integration tests need Docker)
dotnet test --project tests/CSAdvent.UnitTests   # Unit tests only
dotnet tool restore                # Restores dotnet-ef from dotnet-tools.json
dotnet ef migrations add <Name> --project src/CSAdvent.Web --output-dir Data/Migrations
```

**Development-only endpoints:** `/dev/signin?login=...&id=...` (needs `Accounts:DevSignIn`, set by the AppHost in run mode), `/dev/emails` (previews every email), and `POST /dev/{reminders,backups,blurbs,social,social/signups,announcements,digest,links,snapshots}/run?at=…&year=…` (plus `/dev/links/email`), which run a background job as if it were `at`. Locally, social posting and the blurb check are dry runs, fetched pages are samples (`*.csadvent.test`), and Wayback Machine snapshots are a stand-in, so nothing reaches the internet.

## Architecture

| Project | Role |
|---|---|
| `src/CSAdvent.AppHost` | Aspire app model, and production's Azure model (`infra/*.bicep` for DNS, email, alerts, data protection) |
| `src/CSAdvent.ServiceDefaults` | OpenTelemetry, health checks, resilience, service discovery |
| `src/CSAdvent.Web` | Blazor Web App, in feature folders (`Claims/`, `Blurbs/`, `Social/`, `Email/`, `Jobs/`, …); `Data/` holds the entities and migrations |
| `tests/CSAdvent.UnitTests` | xUnit v3 on Microsoft.Testing.Platform, bUnit for components; no database or containers |
| `tests/CSAdvent.IntegrationTests` | Starts the AppHost via `Aspire.Hosting.Testing`; web and database tests |

- **Package versions** are central in `Directory.Packages.props`. Target framework, nullable and warnings-as-errors are in `Directory.Build.props`.
- **Static SSR only:** no interactive render mode and no Blazor script (#185). Every form is a static SSR `EditForm` or a plain form posting to a minimal API. `App.razor` loads only `js/copy.js` and `js/countdown.js`. Bringing the Blazor script back brings back enhanced navigation (double-counted `/go` clicks, #150); an interactive render mode puts an antiforgery token on every page (#186) and breaks `SeasonAccess`, since a circuit has no request.
- **Migrations** run through Aspire's EF Core migrations integration locally, and as a Container Apps job that `aspire deploy` runs before it updates the web app (`MigrateFirst.cs`, #151). Never at app startup.

## Seasons and Time

- **Nothing about time is stored.** A slot is open or claimed by whether it has an author. Reveals (midnight in `Advent:TimeZone`) and every other date come from `Calendar/AdventSchedule`. **Never write `new DateOnly(year, 12, day)`**: use `AdventSchedule.GetDate`, because the test season's rehearsal moves every date.
- **Nothing about a post shows before its reveal** (#5): title, link, summary, card, RSS item, search match, digest line. Check the reveal in C#, not SQL.
- **A season ends twice:** `IsLastDayRevealed` (midnight on December 25) and `IsFinished` (the end of December 25). Pick the one you mean.
- **Background work is given `now`** (#184). `AdventSchedule`'s time questions, `SeasonAdminService.GetCurrentYearAsync` and others have overloads taking it: use them wherever a `now` is in scope. Pages read the real clock.
- Times are entered in the reveal time zone and stored in UTC. Emails describe a time with `AdventSchedule.Describe`.
- Organizer pages work on the current season (the earliest that isn't finished), and show `NoCurrentSeason` when every season is finished.

## The Test Season

- `Season.TestYear` (9000) is a hidden season for rehearsals, with its own dates (`seasons.rehearsal_starts_on`), testers and organizer pages (`?year=9000`, `/manage/testing`).
- **Only testers and organizers can see it** (`SeasonAccess.CanSee`). Any new public page that reads a season's spots must check it; to everyone else the test season's pages are 404s. Without a request, nobody is a tester.
- It's never in RSS, the sitemap, structured data, social posts, retrospectives, archive exports or the organizers' current season. Background jobs read it straight from the database.

## Data

- Entities and their EF configuration live together in `Data/`, one file each. Names are snake_case (`SnakeCaseNamingConvention`), so raw SQL in check constraints and filters uses snake_case.
- **`slots` is public and never holds an email.** Contact details live in `slot_contacts`, `contributors`, `claim_requests` and `substitutes`.
- **Concurrency:** `xmin` row versions. Edit forms post the row's `xmin` back, so a stale edit is refused rather than overwriting.
- **Expected database errors** are named in catch filters: `catch (DbUpdateException e) when (e.IsUniqueViolation())` (`Data/DatabaseErrors`). `ExecuteUpdate`/`ExecuteDelete` throw the `PostgresException` itself.
- **EF Core logs a failed command at Error before any catch runs**, and errors page the organizers. So don't insert a record on every run for a unique index to refuse: load what's recorded and skip it, and keep the index as the guard against two runs at once (#157, `ExpectedErrorTests`).
- **Each migration must work with the code before it:** the old revision serves while migrations run and after a failed deploy, and a rollback runs older code on the newer schema. Add first, remove in a later release. **No migrations from December 1 to 26.** Unit tests fail if the model changes without a migration.
- **History** is `Data/Archive/{year}.json`, seeded by `ArchiveSeeder` (EF Core's `UseSeeding`) only for missing seasons, so editing the JSON doesn't change a seeded database. Locally, **Reset Database** on the `migrations` resource reseeds.

## Pages and Forms

- **SSR forms:** `[SupplyParameterFromForm(FormName = ...)]` on a nullable model, `Form ??= new()` to tell a GET from a POST, and `@bind-Value="Form!.Field"`. Create every form model before the first `await` (#109).
- **Forms that can disappear after a post** (a double click, a spot taken meanwhile) must still render, hidden, when posted, or Blazor answers with a 400 (#142).
- **One form per item** (per row, per card) is a plain form posting to a minimal API, since Blazor form names must be unique. **Minimal API POSTs only check antiforgery if they bind form data**; otherwise call `IAntiforgery.IsRequestValidAsync`. Return URLs go through `ReturnUrl.WithQuery`.
- **Organizer pages** under `Components/Pages/Manage` require the `Admin` policy through that folder's `_Imports.razor`. Their tables sit in a `relative overflow-x-auto` wrapper.
- **A link to `#id` needs the page's own address** (`Navigation.ToBaseRelativePath(Navigation.Uri)`), because a bare `#id` resolves against `<base href>`.
- **Only one `HeadContent` renders**; `SocialMeta` owns it on public pages, so put other head tags in its child content.
- **Don't use `[StreamRendering]`**: pages render into memory for their ETag (`PageCaching`).
- **Form errors:** the `ValidationSummary` in a `<div role="alert">`, and each field's `ValidationMessage` in `<div id="{field}-error">`, named in the input's `aria-describedby` with its help text (`{field}-help`).
- Text is `slate-500` or darker. Component tests use bUnit (`BunitContext`), with `CalendarFixtures` for a season seen on a given date.

## Styling

- **Tailwind CSS 4**, built by `build/Tailwind.targets` during `dotnet build` from `Styles/app.css` into `wwwroot/app.css` (generated and gitignored: never edit it). It only scans `Components` and `wwwroot/js`, so write class names out in full.
- Brand colors are `advent-*` in `@theme`: `advent-600` is the logo blue, `advent-400` the snowflake (too faint behind body text).
- Photos are WebP with a JPEG fallback in `<picture>` with `@Assets` URLs (fingerprinted). Don't use `url()` in `app.css` for images.

## Security and Privacy

- **Content-Security-Policy:** no inline scripts, inline event handlers or `javascript:` links; put scripts in `wwwroot/js`. Images only come from the site, except on `/manage`.
- **Fetching an address someone typed** (logos, blurb checks, dead-link checks, the Wayback Machine) uses its own `HttpClient` with `PublicAddresses.ConnectCallback`, `UseProxy = false` and no factory retries.
- **Social publishers** share an `HttpClient` without retries (a retry could post twice), and send the post with `SocialPostRequests.SendPostAsync`, which tells "failed" from "may have posted" (#154). The author's words in a post go through `AnnouncementFormatter.Inert`.
- **Every link we publish goes through us**: `/go/{year}/{day}/{part}` or the entry page, tagged `?via=` (`EntryVia`), and redirects only to the entry's own post (or its saved copy), so it's never an open redirect. Click counts keep no IP, cookie or user agent.
- **Keep `/privacy` true:** anything that collects or shares something new updates it and its "Last updated" date in the same PR. New personal data goes in the private tables and into `ContactRetention`. No GitHub logins or email addresses in logs or telemetry.
- **Health checks:** never make one Unhealthy for anything but the database, or readiness takes every replica out of service.

## Email

- **Each email is an `EmailContent`** with a template next to its feature (`Claims/ClaimEmails.cs`), rendered to HTML and text by `EmailComposer`. Send with `EmailComposer.TrySendAsync`; if it returns false, undo whatever you recorded so a later run retries. Organizers' emails go to `SiteOptions.OrganizersInbox`.
- **Every new email:** add it to `EmailCatalog` (its `Kind`), mark it **transactional** (about a spot, request or offer they signed up for: no unsubscribe link) or **optional** (has one), and update `OptOutAwareEmailSenderTests`.
- **Email HTML** is tables and inline styles only. Email images use stable paths (`images/csadvent-logo.png`, `images/email-header.jpg`): never rename or remove them.
- **Everything is queued** in `email_outbox` and sent under Azure Communication Services' 30 a minute and 100 an hour (`Email:Queue`). Set `Priority`, `SendBefore` and `Reference` with `content with { ... }` before composing.
- **Once-only emails** are recorded (`sent_reminders`, or a conditional update) before they're queued, and the record is undone if queueing fails.

## Background Jobs

- Workers derive from `Jobs/PeriodicWorker` and list their steps in `JobSteps.All`. Each step runs in its own scope and try/catch; per-spot work uses `EachSpot`. A missing table or column (`MissingSchema.IsMissingTableOrColumn`) is a warning, for a revision started without its migrations (#225).
- **Replicas never duplicate work:** claim it first, with a lease (`leased_until`), a conditional update or a unique index.
- The AppHost turns most workers off in the Testing environment; tests drive them through `/dev/*/run?at=` or `RunOnceAsync`. The email queue's worker runs everywhere, the tests included.

## Testing

- **Integration tests** use `TestBrowser` (`fixture.SignInAsync`, `browser.PostFormAsync(path, formName, fields)`) and `TestSeasons.EnsureAsync`. Each test class uses its own years, all after 2089; grep `EnsureAsync` before picking new ones.
- **Tests must pass in any order, alone, and on a busy machine** (#198):
  - A test creates the data it reads, and asserts on its own rows, not whole pages or tables other classes write to.
  - Never derive a run's time from the real clock: use a fixed time in the season's own year, or one derived from what was saved. Pages counting days by the real clock are asserted with `AssertContainsDaysUntil`.
  - Wait on a condition, never a fixed time.
- **Emails:** `fixture.WaitForEmailAsync(to, subject, containing)` searches MailPit. Pass `containing:` with text only your test's email has, since organizer emails share an address and subject. To check one *wasn't* sent, count `email_outbox` rows about your spot, not MailPit.
- Failures are injected with triggers only the test database gets.

## Hosting

- **Deploys** run from `.github/workflows/deploy.yml` after CI passes on `main`: `aspire deploy` runs the migrations job, then updates the web app, then the workflow checks the new revision is serving.
- **Never publish test runs in the Production environment**: publish and deploy share saved state (`~/.aspire/deployments/`). Use `aspire publish --output-path <dir> --environment PublishCheck`.
- **Change Azure through the AppHost, never the portal:** DNS records in `infra/dns.bicep`, custom domains in `CustomDomains` (every deploy replaces what isn't in the model), alert recipients through the `alert-emails` secret, and `Web:MinReplicas` in a PR. The exception: the ACS email service, sending domain and sender are create-only (`@onlyIfNotExists()`), so a live change to them is made in the portal.
- **Secrets** (social credentials, `anthropic-api-key`, `wayback-keys`, `alert-emails`) are added only when published *and* given a value, so a missing one never breaks a deploy.
- **Never delete the `data-protection` Key Vault key**, and never point the site at a restored database server (copy the data back instead).
- CI skips documentation-only changes in three lists (`ci.yml`'s `paths-ignore` and its "Check for code changes" step, and `deploy.yml`'s "Choose the commit"). Keep them in step.

## Decisions (don't undo without asking)

- **Readers go straight to the post** (2026-10-26): entry pages redirect everyone but link previews and organizers to the post, counting a click. `/go` and entry pages are crawlable, with `X-Robots-Tag: noindex` (#167).
- **No analytics** (2026-10-23); the click counts are enough.
- **Authors' email addresses are kept** (2026-10-25) so they hear about the next season; requests and backup lists are deleted on February 1.
- **Emails are transactional or optional** (2026-10-25), as above.
- **Posts reach the calendar only through My spots**, never by replying to an email.
- **No more email capacity from Azure** (#136), and **no scheduled `pg_dump`** (2026-10-26): 35-day point-in-time backups (the privacy page says so) and the yearly archive JSON instead.

## Gotchas

- **AngleSharp is pinned to bUnit's version** (1.8.5): 1.8.6 breaks bUnit 2.12.5. Update them together.
- **EF Core 11 with Aspire 13.6:** `Npgsql.EntityFrameworkCore.PostgreSQL` 11.x is referenced directly (Aspire's package has no `net11.0` build). `dotnet-ef` is pinned twice (`dotnet-tools.json` and `WithToolVersion` in `AppHost.cs`); update both.
- **`dotnet ef migrations remove` needs a database**: use **Remove Migration** on the `migrations` resource, or delete the two files and restore `AdventDbContextModelSnapshot.cs` from git. EF Core 11 refuses `database update` with no migrations, hence the empty `InitialCreate`.
- **User secrets are shared with the tests:** if local Postgres rejects its password, delete the `*-postgres-data` Docker volume.
- **Don't call `CreateResourceBuilder(web).WithEnvironment(...)` in the test fixture**: the web app then runs as Production. Put test-only settings in the AppHost's `isTesting` branch, and keep that branch when changing resources.
- **The web app's logs in test output** show as `fail: CSAdvent.AppHost.Resources.web[0]` whatever their level; read the `warn:` or `fail:` inside the line. Information logs never reach the output.
- **Blazor's form binding sets a list property to null** when none of its fields were posted; turn null into an empty list in the setter.
- **`.gitignore` ignores `/Backup*/` at the root only**; if new files vanish from `git status`, try `git check-ignore -v <path>`.
- **At .NET 11 GA (#55):** update `global.json`, EF Core, Npgsql, Aspire, `dotnet-ef` (both places) and the migrations job's base image tag and digest in `AppHost.cs`, then drop those packages from Dependabot's `ignore`.
